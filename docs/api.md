# FistBump Backend API

Routes exposed by the Go backend (`fistbump-core`). Only the Electron main process calls it. See [architecture.md](architecture.md) for the design and [schema.md](schema.md) for tables.

Table and column names under "DB" are provisional and predate the final schema. Align with [schema.md](schema.md).

## Conventions

**Transport**
- HTTP/1.1 on `127.0.0.1`, random port, JSON bodies (`Content-Type: application/json`) unless noted.
- Every request needs `Authorization: Bearer <token>`. The token is generated by Electron per launch and passed to Go in the `FISTBUMP_TOKEN` environment variable. A missing or wrong token returns `401`.
- All routes live under `/v1`.

**Process contract (not HTTP)**
- Flags: `--data-dir <path>`.
- stdout: exactly one line, `PORT=<n>`, once the listener is ready. Nothing else is ever written to stdout.
- stderr: logs. Request logs never include `Authorization` or request bodies for secret-bearing routes.
- The process exits when stdin closes.

**Identifiers and formats**
- Integer ids. Dates are `YYYY-MM-DD`. Timestamps are RFC 3339 UTC.
- Unknown JSON fields in a request are rejected with `422`.
- List routes return a bare JSON array unless noted.

**Error shape**

```json
{ "error": { "code": "validation_failed", "message": "email is not valid", "details": { "field": "email" } } }
```

| Status | `code` | Meaning |
|--------|--------|---------|
| 400 | `bad_request` | Malformed JSON or query |
| 401 | `unauthorized` | Missing or wrong bearer token |
| 404 | `not_found` | No such resource |
| 409 | `conflict` | State forbids the action (for example pending suggestions) |
| 422 | `validation_failed` | Well-formed but invalid fields |
| 500 | `internal` | Unexpected error (panic recovery also lands here) |
| 502 | `upstream_error` | A remote API or connector failed |
| 503 | `ai_unavailable` | Requested provider cannot run (only when the caller forced one) |

AI routes do not fail on a missing model. They fall back to rule-based output and report which provider ran (`provider`, `fallback`).

## Shared shapes

```jsonc
// Profile
{ "id": 1, "name": "", "email": "", "phone": "", "location": "", "links": ["https://..."], "summary": "" }
// Experience
{ "id": 1, "company": "", "title": "", "start_date": "2022-06-01", "end_date": null, "bullets": ["..."], "position": 0 }
// Education
{ "id": 1, "school": "", "degree": "", "start_date": "2018-09-01", "end_date": "2022-05-01" }
// Job
{ "id": 1, "title": "", "company": "", "url": "", "source": "paste|greenhouse", "keywords": ["go", "sql"],
  "raw_text": "", "searched_at": "2026-10-04T12:00:00Z" }
// Suggestion
{ "id": 1, "revision_id": 1, "target_ref": "experience:3:bullet:1", "original_text": "", "suggested_text": "",
  "edited_text": null, "status": "pending|accepted|rejected|edited" }
// Application
{ "id": 1, "job_listing_id": 1, "tailored_resume_id": null, "status": "saved|applied|interviewing|offered|archived",
  "applied_date": null, "notes": "", "links": [] }
```

## Resume (`resume.go`)

The v1 app has one master resume. The aggregate view joins profile, experiences, education, and skills.

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/resume` | none | `{ "profile": Profile, "experiences": [Experience], "education": [Education], "skills": ["go"] }` (empty profile if none yet) | SELECT from `profile`, `experience` (by `position`), `education`, `resume` |
| `PUT /v1/resume/profile` | Profile fields without `id` | Profile | Upsert `profile` row |
| `GET /v1/resume/experiences` | none | `[Experience]` ordered by `position` | SELECT `experience` |
| `POST /v1/resume/experiences` | Experience without `id`. `company` and `title` required. `end_date` null means current. | `201` Experience | INSERT `experience`, `position` set to next value |
| `PUT /v1/resume/experiences/{id}` | Experience fields (full replace) | Experience | UPDATE `experience`. `404` if missing. |
| `DELETE /v1/resume/experiences/{id}` | none | `204` | DELETE `experience` |
| `GET /v1/resume/education` | none | `[Education]` | SELECT `education` |
| `POST /v1/resume/education` | Education without `id`. `school` required. | `201` Education | INSERT `education` |
| `PUT /v1/resume/education/{id}` | Education fields | Education | UPDATE `education` |
| `DELETE /v1/resume/education/{id}` | none | `204` | DELETE `education` |
| `GET /v1/resume/skills` | none | `{ "skills": ["go", "sql"] }` | SELECT `resume.skills` |
| `PUT /v1/resume/skills` | `{ "skills": ["go", "sql"] }`. Trimmed, de-duplicated, case-insensitive. | Same shape, normalized | UPDATE `resume.skills`, `updated_at` |

Validation: dates must be valid and `end_date >= start_date`; bullets are trimmed and empty ones dropped.

## Jobs (`jobs.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `POST /v1/jobs/parse` | `{ "raw_text": "..." }` | `{ "cleaned_text": "", "keywords": [], "requirements": [] }` | None (stateless preview) |
| `POST /v1/jobs` | `{ "title", "company", "url", "raw_text", "source": "paste" }`. `raw_text` required. Missing title or company is inferred where possible. | `201` Job. If the same URL already exists, `200` with the existing Job and a refreshed `searched_at`. | Runs `parser`, then INSERT `job_listing` with keywords, or UPDATE `searched_at` on re-import |
| `GET /v1/jobs` | Query: `q` (title/company substring), `limit`, `offset` | `[Job]` without `raw_text`, newest first | SELECT `job_listing` |
| `GET /v1/jobs/{id}` | none | Job with `raw_text` | SELECT `job_listing` |
| `DELETE /v1/jobs/{id}` | none | `204`. `409` if an application references it. | DELETE `job_listing` after checking `application` |
| `POST /v1/jobs/{id}/analyze` | none | see below | SELECT `job_listing`, `profile`, `experience`, `education`, `resume`. No writes. |

Analyze response (deterministic, never calls an AI provider, target under 1.5 s):

```json
{
  "job_id": 1,
  "matched": [{ "keyword": "go", "evidence": ["experience:2:bullet:0"] }],
  "missing": ["kubernetes"],
  "score": 0.62,
  "duration_ms": 14
}
```

## Revisions (`revisions.go`)

A revision is one AI (or fallback) pass that proposes suggestions for a job.

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `POST /v1/revisions` | `{ "job_listing_id": 1, "provider": "auto" }`. `provider` is `auto` (default), `local`, `remote`, or `fallback`. | `202` Revision: `{ "id", "job_listing_id", "status": "generating", "provider", "fallback": false }` | INSERT `revision`. Suggestions are INSERTed as the provider returns them. |
| `GET /v1/revisions` | Query: `job_id` | `[Revision]` | SELECT `revision` |
| `GET /v1/revisions/{id}` | none | Revision plus `"suggestions": [Suggestion]`. `status` is `generating`, `ready`, or `failed`. On `failed`, `error` is set. | SELECT `revision`, `suggestion` |
| `DELETE /v1/revisions/{id}` | none | `204` | DELETE `revision` (cascades to `suggestion`) |
| `POST /v1/revisions/{id}/suggestions/{sid}/accept` | none | Suggestion with `status: "accepted"` | UPDATE `suggestion.status` |
| `POST /v1/revisions/{id}/suggestions/{sid}/reject` | none | Suggestion with `status: "rejected"` | UPDATE `suggestion.status` |
| `POST /v1/revisions/{id}/suggestions/{sid}/edit` | `{ "edited_text": "..." }` (non-empty) | Suggestion with `status: "edited"` | UPDATE `suggestion.edited_text`, `status` |

Generation runs in the background. Electron polls `GET /v1/revisions/{id}` until `status` leaves `generating`. If the provider errors mid-run, the backend retries with the next provider and sets `fallback: true`. Suggestions are bullet-level and point at their source through `target_ref`. The prompt contains only the master resume text and the posting text.

## Tailored resumes (`tailored.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `POST /v1/tailored-resumes` | `{ "revision_id": 1 }` | `201` `{ "id", "revision_id", "content", "created_at" }`. `409 conflict` with `details.pending` (count) if any suggestion is still `pending`. | Reads `suggestion`, master resume tables. INSERT `tailored_resume` with accepted and edited text applied. Rejected suggestions keep the original bullet. |
| `GET /v1/tailored-resumes` | Query: `job_id` | `[TailoredResume]` without `content` | SELECT `tailored_resume` joined to `revision` |
| `GET /v1/tailored-resumes/{id}` | none | TailoredResume with `content` | SELECT `tailored_resume` |
| `GET /v1/tailored-resumes/{id}/diff` | none | `{ "hunks": [{ "target_ref", "status": "unchanged|changed|added|removed", "before", "after", "words": [{ "op": "eq|add|del", "text" }] }] }` | SELECT `tailored_resume`, master resume tables. Diff computed in `diff`, not stored. |
| `POST /v1/tailored-resumes/{id}/export` | `{ "format": "pdf" }` or `"md"` | Raw bytes. `Content-Type: application/pdf` or `text/markdown`, plus `Content-Disposition: attachment; filename="..."`. | SELECT `tailored_resume`. No writes. |
| `DELETE /v1/tailored-resumes/{id}` | none | `204`. `409` if an application references it. | DELETE `tailored_resume` |

Export returns bytes. Electron shows the save dialog and writes the file, so Go never accepts a filesystem path from the UI. On PDF failure the response is `500` and the UI offers `md`.

## Applications (`applications.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/applications` | Query: `status`, `q` | `[Application]` plus `job_title` and `company` from the job | SELECT `application` JOIN `job_listing` |
| `POST /v1/applications` | `{ "job_listing_id", "tailored_resume_id"?, "status"?, "applied_date"?, "notes"?, "links"? }`. Status defaults to `saved`. | `201` Application | INSERT `application`. `422` if the job id is unknown. |
| `GET /v1/applications/{id}` | none | Application | SELECT `application` |
| `PUT /v1/applications/{id}` | Any subset of `status`, `applied_date`, `notes`, `links`, `tailored_resume_id` | Application | UPDATE `application`. Moving to `applied` with no date sets today's date. |
| `DELETE /v1/applications/{id}` | none | `204` | DELETE `application` |

## Connectors (`connectors.go`)

The only routes that can reach a job site. Each call needs the connector enabled.

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/connectors` | none | `[{ "id": "greenhouse", "name": "Greenhouse", "enabled": false, "query_fields": [{ "name": "board", "label": "Company board id", "required": true }] }]` | Reads `settings` (`connector.<id>.enabled`) |
| `PUT /v1/connectors/{id}` | `{ "enabled": true }` | Connector | UPSERT `settings` |
| `POST /v1/connectors/{id}/fetch` | `{ "query": { "boards": ["acme"], "categories": ["cybersecurity"], "keywords": ["backend"], "location": "", "work_mode": "" } }`. When `boards` and `categories` are both omitted, the searched set is `connectors.greenhouse.boards` plus the boards of `connectors.greenhouse.categories`. Omitted filters default to the profile's `target_positions` and `preferred_mode`. | `{ "postings": [{ "external_id", "board", "title", "company", "url", "location", "raw_text", "score" }], "boards_searched": 18, "errors": [{ "board", "message" }] }`. Sorted by `score`. A failing board appears in `errors` and does not fail the request. | Reads `settings`, `profile`, `experiences`. No writes. Results are cached in memory. |
| `GET /v1/connectors/greenhouse/categories` | none | `[{ "id": "ai_ml", "name": "AI and machine learning", "parent": "technical", "board_count": 30, "enabled": false }]`. `parent` is null for top-level categories. `board_count` counts the category's own boards. Includes a `notice` field stating the lists are not exhaustive. | Reads `connectors.greenhouse.categories` from `settings`. Category data comes from embedded `boards.json`. |
| `PUT /v1/connectors/greenhouse/categories/{category}` | `{ "enabled": true }` | The category entry. `404` for an unknown category id. | Updates `connectors.greenhouse.categories` in `settings`. Enabling a parent covers its subsets when searching. |
| `POST /v1/connectors/greenhouse/boards` | `{ "board": "acme" }` | `{ "board": "acme", "company": "Acme Inc", "open_postings": 42 }`. `422` if the board does not exist. | Appends to `connectors.greenhouse.boards` in `settings` after validating the token upstream |
| `DELETE /v1/connectors/greenhouse/boards/{board}` | none | `204` | Removes the token from `connectors.greenhouse.boards` |
| `POST /v1/connectors/{id}/import` | `{ "query": {...}, "external_ids": ["123"] }`. Omit `external_ids` to import all matching results. | `{ "imported": [Job], "refreshed": [Job] }` | Upsert `jobs` on `(source, external_id)`. Existing rows get a new `searched_at`. |

Errors: `409` if disabled, `422` for a bad query, `502` with the upstream status on failure or rate limit. Requests use HTTPS with a timeout and a response size cap.

## AI (`ai.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/ai/status` | none | `{ "mode": "auto", "active_provider": "local", "local": { "model": "", "installed": true, "running": false }, "remote": { "configured": true, "base_url": "", "model": "", "has_key": true } }` | Reads `settings` |
| `PUT /v1/ai/mode` | `{ "mode": "auto" }`. One of `auto`, `local`, `remote`, `fallback`. | Same as status | UPSERT `settings` (`ai.mode`) |
| `PUT /v1/ai/remote` | `{ "base_url": "https://api.example.com/v1", "model": "name", "api_key": "..." }`. `api_key` is optional (omit for keyless Ollama). `base_url` must be HTTPS unless the host is loopback. | Same as status. The key is never echoed back. | UPSERT `settings` for `base_url` and `model`. **The key is held in memory only and never written to the DB.** |
| `DELETE /v1/ai/remote` | none | `204` | Clears remote settings; drops the in-memory key |
| `POST /v1/ai/test` | `{ "provider": "local" }` or `"remote"` | `{ "ok": true, "latency_ms": 840, "sample": "pong", "error": null }`. Failures return `ok: false` with `error`, still `200`. | None |

Electron calls `PUT /v1/ai/remote` at every launch to supply the stored key. See "API keys and secrets" in architecture.md.

## Models (`models.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/models` | none | `[{ "id", "repo", "file", "size_bytes", "min_ram_gb", "installed": false, "fits_this_machine": true, "selected": false }]` | Catalog from embedded `catalog.json`, installed state from disk, `selected` from `settings` (`ai.local_model`) |
| `GET /v1/models/{id}` | none | One model entry | Same |
| `POST /v1/models/{id}/download` | none | `202` `{ "download_id": "abc" }`. `409` if already installed or already downloading. | None. Writes a `.part` file in the data dir. |
| `GET /v1/models/downloads/{download_id}` | none | `{ "state": "running|verifying|done|failed|cancelled", "bytes": 0, "total": 0, "error": null }` | None |
| `DELETE /v1/models/downloads/{download_id}` | none | `204`, stops the transfer. The `.part` file is kept so a later download can resume. | None |
| `DELETE /v1/models/{id}` | none | `204`. Stops the local server first if this model is loaded. | Deletes the file. Clears `ai.local_model` if selected. |
| `PUT /v1/models/token` | `{ "token": "hf_..." }` (optional Hugging Face token for gated models) | `204` | In memory only |
| `DELETE /v1/models/token` | none | `204` | Drops the in-memory token |

Downloads use HTTP range requests to resume, verify SHA-256 against the catalog, then atomically rename the `.part` file. A hash mismatch ends in `failed` and the file is deleted.

## Settings (`settings.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/settings` | none | `{ "ai.mode": "auto", "ai.local_model": "", "ai.idle_timeout_min": 10, "jobs.retention_days": 90, "connector.greenhouse.enabled": false }` with defaults filled in | SELECT `settings`, defaults applied in `store/settings.go` |
| `PUT /v1/settings` | A subset of the keys above, for example `{ "jobs.retention_days": 60 }` | Full settings map | UPSERT `settings`. Unknown keys and secret-looking keys are rejected with `422`. |

Settings never hold secrets.

## Storage (`storage.go`)

| Route | Request | Response | DB |
|-------|---------|----------|----|
| `GET /v1/storage` | none | `{ "data_dir", "db_bytes", "models_bytes", "cache_bytes", "partial_downloads_bytes", "job_count", "total_bytes" }` | `COUNT` on `job_listing`, file sizes from disk |
| `POST /v1/storage/cleanup` | `{ "targets": ["cache", "partial_downloads", "old_jobs", "unused_models"], "older_than_days": 90, "dry_run": false }` | `{ "freed_bytes": 0, "removed": { "old_jobs": 12, "files": 3 }, "dry_run": false }` | `old_jobs`: DELETE from `job_listing` where `searched_at` is older than the cutoff and no `application` references the row. Then `VACUUM`. |

The UI calls with `dry_run: true` first to preview removals.
